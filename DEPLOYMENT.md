# Deploying Bruno's Deli & Pizza

A live link you can send someone to try the site, at $0/month: Render (free
web service) hosting one Node process that serves both the API and the
built frontend, backed by a free hosted Turso (SQLite-compatible) database
so data survives restarts.

## 1. Push this repo to GitHub

If you haven't already:

```bash
git remote add origin https://github.com/<you>/<repo>.git
git push -u origin master
```

## 2. Create the database (Turso)

1. Sign up at [turso.tech](https://turso.tech) (free).
2. Install the CLI and log in: see their site for your OS's install command,
   then `turso auth login`.
3. Create a database and grab its connection details:
   ```bash
   turso db create bruno-pizza
   turso db show bruno-pizza --url          # → TURSO_DATABASE_URL (starts with libsql://)
   turso db tokens create bruno-pizza        # → TURSO_AUTH_TOKEN
   ```
4. Apply the schema (one-time; repeat this step for any future migration):
   ```bash
   turso db shell bruno-pizza < backend/prisma/migrations/20260908035204_init_sqlite/migration.sql
   ```
5. Seed the menu data. Easiest way: run it from your machine, pointed at Turso:
   ```bash
   cd backend
   TURSO_DATABASE_URL="<url from step 3>" TURSO_AUTH_TOKEN="<token from step 3>" npx tsx prisma/seed.ts
   ```

Keep the URL and token from step 3 — you'll paste them into Render next.

## 3. Deploy to Render

1. Sign up at [render.com](https://render.com) (free) and connect your GitHub account.
2. **New > Blueprint**, pick this repo. Render reads `render.yaml` at the repo
   root and proposes one web service (`bruno-pizza`).
3. Before the first deploy, fill in the environment variables Render prompts
   for (marked `sync: false` in `render.yaml`):
   - `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` — from step 2.3 above.
   - `ADMIN_EMAIL`, `ADMIN_PASSWORD` — login for `/admin/login` (the staff order dashboard).
   - `EMAIL_USER`, `EMAIL_PASSWORD` — a Gmail address + [App Password](https://myaccount.google.com/apppasswords) (not your normal password) if you want real order-notification emails. Leave blank to just log emails to Render's console instead.
   - `EMAIL_FROM` — e.g. `Bruno Pizza <youraddress@gmail.com>`.
   - `RESTAURANT_EMAIL` — where new-order notifications get sent.
   - `FRONTEND_URL` — leave blank for now; see step 4.
   - `JWT_SECRET` is auto-generated by Render, no action needed.
4. Deploy. First build takes a few minutes (installs deps, builds both
   frontend and backend).

## 4. Finish the URL setting

Once deployed, Render shows your service's URL, e.g.
`https://bruno-pizza.onrender.com`. Open the service's **Environment** tab,
set `FRONTEND_URL` to that exact URL, and save (triggers a quick redeploy).
This isn't strictly required for the site to work — frontend and backend
share one origin — it just keeps CORS headers accurate.

## 5. Send the link

That's it — `https://bruno-pizza.onrender.com` (or whatever Render assigned)
is what you send your client. A couple of things worth knowing:

- **Free tier sleeps after 15 minutes idle.** The first request after that
  takes ~30-50 seconds while it wakes up; after that it's normal speed.
- **Order confirmation/notification emails** only send for real if you set
  `EMAIL_USER`/`EMAIL_PASSWORD` (step 3) — otherwise they're just logged in
  Render's log viewer, which is fine for a demo.
- **Staff/admin dashboard** is at `/admin/login` using the `ADMIN_EMAIL`/
  `ADMIN_PASSWORD` you set.

## Future schema changes

If you (or I) change `backend/prisma/schema.prisma` later, generate a new
migration locally (`npm run db:migrate -w backend`), then apply just the new
migration's SQL file to Turso the same way as step 2.4 above.
